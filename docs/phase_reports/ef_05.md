# EF-05 Phase Report: Reusable Survey Cleaning

## Outcome

The EF cleaning pipeline now reads Google Forms-style CSV/XLSX/XLS exports,
maps canonical survey columns conservatively, applies configurable training or
scoring quality rules, and writes canonical Parquet plus a JSON quality report.
The CLI, retraining validation, and website-upload quality-report path call the
same `EnvironmentalFinancialCleaner`.

The existing production scorer still uses the previous model feature schema.
The EF cleaner therefore supplies upload quality findings while scoring
continues through the existing schema aligner. Confirmed retraining explicitly
fails when the cleaned EF questionnaire does not satisfy the legacy model's
feature contract; it no longer reports success after training from unrelated
preprocessed files. The retraining API now calls the implemented validation
function and uses `at_risk` as the default outcome.

## Work completed

- Added schema-driven CSV, XLSX, and XLS loading, encoding/header detection,
  text normalization, exact/normalized mapping, and non-automatic fuzzy
  suggestions.
- Added consent and attention filtering, codec conversion, per-item range
  validation, special-answer handling, online derivation, consistency flags,
  duplicate policy, straight-line detection, missingness policy, outcome
  derivation, and per-stage audit logs.
- Added training/scoring behavior, row-level scoring reasons, missingness and
  class-balance summaries, item distributions, warnings, and traffic-light
  messages.
- Added the `python -m mei.cli clean` command and Parquet/JSON persistence.
- Routed API uploads through the shared cleaner for quality reporting and fixed
  the retraining endpoint to call the real validation function.
- Added focused cleaner and retraining-integration tests and
  `docs/04_cleaning.md`.

## Scope and limitations

The sample results are synthetic pipeline checks, not real survey evidence.
Imputation remains inside the model pipeline. The current legacy inference model
does not yet accept the EF canonical feature set, so this phase does not claim
that uploaded EF fields are already used for production scoring or confirmed
model retraining.
